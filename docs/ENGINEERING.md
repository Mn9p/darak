# DARAK (دارك) — Engineering Conventions

Property Management & Real Estate Operations Platform. Arabic RTL-first, SAR currency, Saudi market.
Stack: **pnpm + Turborepo monorepo. `apps/web` = Next.js 15 (App Router, React 19, Server Components + Server Actions), TypeScript strict, Tailwind v4, jose sessions, zod. `packages/db` = `@darak/db`: Prisma 6 multi-file schema, SQLite (dev) / PostgreSQL (prod), migrations, client singleton.**

## Commands (run from repo root)
- `pnpm dev` — dev server. `pnpm typecheck` — type check all workspaces (must pass). `pnpm test` — vitest. `pnpm build`.
- `pnpm db:reset` — delete SQLite DB, push schema, run the clean seed (no example data; only `SUPER_ADMIN_PHONES` admins). `pnpm db:reset:demo` / `pnpm db:seed:demo` — opt-in demo office for local testing and the smoke test. `pnpm db:push` / `pnpm db:seed` / `pnpm db:generate` / `pnpm db:validate` / `pnpm db:studio`.
- `pnpm db:migrate:deploy` — apply Postgres migrations in prod. Before launch: `pnpm --filter @darak/db migrate:diff` regenerates `0001_init/migration.sql` from the schema (read-only). After launch `0001_init` is frozen: `MIGRATE_FROM_URL=<neon direct url> pnpm --filter @darak/db migrate:new <name>` writes the next migration (read-only diff against the live DB).
- `BASE=http://localhost:3000 pnpm smoke` (server running, after `pnpm db:reset:demo`) — logs in as every demo role, GETs every route, checks tenant isolation.
- Single `.env` at repo root (loaded by `apps/web/next.config.ts`, `apps/web/scripts/env.ts`, `packages/db/scripts/env.mjs`). SQLite file lives at `packages/db/prisma/schema/dev.db`.
- Never run `prisma db push --force-reset`, `prisma migrate dev` or `prisma migrate reset` (the `packages/db/scripts/prisma.mjs` wrapper refuses them).
- Route guard: `requireStaff()` (lib/auth.ts) maps the request path to its NAV permission via `routePermission()` (lib/nav.ts; middleware sets `x-pathname` on every request) — it runs on every page render, soft navigation and server action, not only in the layout. New top-level modules must be added to `src/lib/nav.ts` with a permission. `hrefPermission(href)` tells whether to show a link/button (view for pages, manage for `/new` and `/edit`). Daily menu is 7 items (property-first); everything else goes under "المزيد".

## Identity
- **Sign-in is by Saudi mobile number + one-time SMS code. No passwords anywhere.** `User.phone` is unique and always stored normalized (`9665XXXXXXXX`) via `normalizePhone()` from `lib/phone.ts`; render with `displayPhone()` inside `<span className="num">`; prefill inputs with `localPhone()`. `User.email` is optional.
- Owner/Tenant records with a phone get their portal account automatically on first sign-in (`login/actions.ts` → `resolveAccount`). **Invite-only:** unknown numbers never receive a code; they are pointed to the landing-page form (`app/request/actions.ts` → `AccessRequest`, inbox at `/admin/requests`). Offices are created only from `/admin/organizations/new` (prefilled from a request). Team contact comes from `SUPPORT_PHONE` / `SUPPORT_EMAIL` (`lib/support.ts`). Platform admins come from `SUPER_ADMIN_PHONES`. `LOGIN_ALLOWED_PHONES` (optional) restricts sign-in to a fixed list during a closed test (`loginAllowed()` in `lib/auth.ts`).
- Codes: `lib/otp.ts` (5 min, 5 attempts reserved atomically, 60 s resend, hashed at rest; failed sends do not count; per-IP caps on unknown numbers and wrong codes). `LOGIN_ALLOWED_PHONES` restricts sign-in during a closed test. Delivery via `channels.ts`: Authentica (`send-otp` with our own code; OTP only, no free-text SMS), Unifonic or Msegat. Without SMS credentials the code is echoed on screen (`OTP_ECHO=auto`); set `OTP_ECHO=never` once a vendor is configured.

## Non-negotiable rules
1. **Auth + tenancy on every page and action.** Pages: `const user = await requireStaff()` (or `requireRole([...])`, `requireOwner()`, `requireTenant()`, `requireSuperAdmin()`). Every Prisma query filters by `organizationId: user.organizationId` (or via a relation that does). Actions: `assertCan(user, "x.manage")`.
2. **Data scope.** Property-scoped role (PROPERTY_MANAGER) only see assigned properties: spread `propertyScope(user)` (on Property), `propertyIdScope(user)` (entities with propertyId), `contractScope(user)` (installments/payments) into `where`.
3. **Audit everything that mutates**: `await audit({ user, action: "CREATE"|"UPDATE"|"APPROVE"|..., entityType: "CONTRACT", entityId, entityLabel, oldValue, newValue })`.
4. **No hard deletes** of financial/contract data — set status ARCHIVED/CANCELLED/REVERSED. Payments once APPROVED cannot be edited without `payments.approve` (BR-003).
5. **Codes** via `nextCode(orgId, "contract"|"payment"|"expense"|"ownerStatement"|"owner"|"property"|"unit"|"tenant")`.
6. Dates: use helpers in `format.ts` (`date`, `datetime`, `money`, `sar`, `pct`, `relative`, `daysFromToday`, `daysOverdue`, `inputDate`, `addMonths`, `addDays`, `startOfMonth`, `endOfMonth`). Numbers render inside `<span className="num">` (Inter, LTR). Money: `money(v)` + "ر.س" or `<Money value={v} />`.
7. After allocating/reversing payments call `refreshInstallments(orgId, installmentIds)` from engine.ts. When creating a contract use `buildSchedule()` from engine.ts to generate installments. Statement figures: `computeOwnerStatement()`. Grace period follows the statutory rule (`graceDaysFor`: 15 days monthly/quarterly, 30 days semi-annual/annual; org setting `statutoryGrace`); `enforcementEligible()` marks claims past grace; `tenantRisk()` is the deterministic late-payment indicator. Property-level collection queries live in `lib/collections.ts` (`propertyCollectionBoard`, `propertyClaims`).
6a. **Time zone.** Every calendar rule is Riyadh time (UTC+3, no DST) whatever the server zone: use `startOfDay`/`endOfDay`/`startOfMonth`/`endOfMonth`/`startOfYear`/`ksaDate`/`ksaParts`/`inputDate`/`daysBetween` from `format.ts`; never `new Date(y, m, d)`, `setHours`, `getMonth()` or `toISOString().slice(0,10)` for calendar logic. Formatters already use `timeZone: Asia/Riyadh`.
6b. **Owner statements are a ledger.** `computeOwnerStatement(org, owner, start, end, propertyId, { carry: true })` for statements: each source row (allocation / expense) contributes the difference between its truth and what locked statements already paid (`OwnerStatementLine`, frozen by `freezeStatement()` when a statement leaves DRAFT; `unfreezeStatement()` on back-to-draft). Late entries, bounced cheques and edits settle in the next statement; nothing is paid twice. Show a statement with `statementFigures(s)`. Reports use the default (period-only) mode. Ownership shares: `ownershipPctAt` — opening rows cover back-dated history, transfers apply from their start. Expense with `ownerId` → 100% that owner; without → split by ownership. Fee: contract rate for the contract's owner, each co-owner's own rate otherwise; VAT billed with rent, fee on the rent part only.
6c. **Installments.** Schedules come from `lib/schedule.ts` (`buildSchedule` prorates the last installment; same code runs the contract form preview). A waiver lowers `amount` to what was paid and records `waivedAmount` (a later bounced cheque re-opens only the paid part); `openingPaid` holds imported opening balances (`paidAmount = openingPaid + allocations`). Allocation transactions row-lock installments first (`lockRows` in payments/actions.ts).
7a. **Statuses are few on purpose.** Installments: UPCOMING / DUE (due today or inside grace) / OVERDUE / PARTIALLY_PAID / PAID / WAIVED. Collection cases: OPEN / PROMISE_TO_PAY / BROKEN_PROMISE / DISPUTED / ESCALATED / PAID / CLOSED. Contracts: DRAFT / PENDING_APPROVAL / ACTIVE / EXPIRING_SOON / RENEWAL_PENDING / RENEWED / EXPIRED / TERMINATED / CANCELLED. Do not add statuses for things a date or a note already says. Pages call `runEngineThrottled(orgId)` (10-minute cap, database lease shared by every server instance, never throws); cron calls `runEngineLeased`. Auto-tasks exist only for work without its own queue (renewals, expenses, documents, vacant units) — collections are their own queue.
7b. **Collections are property-first.** `/collections` lists properties; the workspace is `/properties/[id]?tab=collections` (`CollectionsTab` + client `ClaimsTable` drawer reusing `collections/actions.ts`). Never add a second mutation path — reuse those actions.
7c. **Assistant** (`lib/ai.ts`): `propertyBrief`, `reminderDraft`, `dailyBrief` take facts (numbers) and return Arabic text; Gemini (`gemini-2.5-flash`, `GEMINI_API_KEY`) when configured, deterministic fallback otherwise. It never writes to the DB; drafts are sent only after the user confirms. Render through `<AssistantCard>` inside `<Suspense>`. Copy never says "ذكي".
8. Notifications/tasks: `notify({...})` and `autoTask({...})` from `notify.ts`.
9. Every list page: `export const dynamic = "force-dynamic"`, `searchParams: Promise<Record<string,string|undefined>>` (await it), `FilterBar` GET filters, `Pagination`, `EmptyState` with CTA. Every 360 page: `Tabs` via `?tab=` and `notFound()` when not in org/scope.
10. Forms: client component `XForm.tsx` with `useActionState<FormState, FormData>(action, null)` and `<form onSubmit={keepFormValues(formAction)}>` (lib/keep-form — React 19 would otherwise wipe the inputs on a validation error); action signature `(_prev: FormState, fd: FormData): Promise<FormState>`, returns `{ error }` or `redirect(…?toast=…)`. Simple one-click mutations: `<ActionButton action={fn} hidden={{ id }} confirm="…">` where `fn(formData: FormData): Promise<void>` (add `confirm` for anything destructive). **Every exported action body is wrapped**: form actions `try { … } catch (e) { return actionFailure(e); }`, button actions `try { … } catch (e) { await failFromError(e); }` (lib/action-error) — Next hides thrown messages in production, the wrapper turns Arabic business errors into a form error / error toast and logs technical ones. Inside inner catches use `userMessage(e, fallback)`, never `(e as Error).message`. `assertCan` redirects to /forbidden. Searches use `textLike(q)` / `phoneLike(q)` (lib/search — case-insensitive on Postgres, any phone spelling).
11. `params` and `searchParams` are Promises in Next 15 — always `await` them.
12. Page files may export only `default`, `metadata`, `dynamic`, `revalidate`. Put shared components elsewhere.
13. Arabic UI copy, professional tone (brand voice: clear, no hype). Saudi market terms: سند قبض (payment), الدفعة المستحقة (installment), كشف حساب المالك (statement), المؤجر/المستأجر, مهلة السداد, طلب تنفيذ عبر ناجز, مفسوخ (terminated). Report titles are Arabic. Errors are human: "تعذر حفظ الدفعة حاليًا. لم يتم تسجيل أي مبلغ." Empty states have a CTA.
14. Status colors: always through `<StatusTag value map={X_STATUS}/>` (constants.ts) — never raw colors; never color alone (label always present).
